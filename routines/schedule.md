# 예약 작업 구성

예약 작업은 실행할 때마다 새 세션을 띄운다. 새 세션은 아무것도 모르는 상태라서, 아래 공통 시작 절차를 먼저 따른다.
시간은 모두 한국 시간(Asia/Seoul)이다. 정각 혼잡을 피하려고 분을 일부러 비껴 두었다.

| 이름 | 시간 | 실행할 절차 | 결과 |
|---|---|---|---|
| 살말 아침 제작 | 매일 08:43 | `daily-research.md` → `daily-produce.md` | 새 소재, 초안, 검수, 승인 요청 |
| 살말 점심 게시 | 매일 12:47 | `daily-publish.md` | 승인된 소재 예약 게시 |
| 살말 저녁 게시·성과 | 매일 19:38 | `daily-publish.md` → `daily-metrics.md` | 예약 게시, 게시 확인, 성과 수집 |
| 살말 주간 보고 | 월요일 09:21 | `weekly-report.md` | 주간 보고, 교훈 갱신 |

완료 알림은 휴대폰 푸시로 받는다.

세션에서 만든 예약 작업에는 커넥터를 붙일 수 없어서, Metricool이 필요한 작업은 사용자가 claude.ai의 예약 작업
화면에서 Metricool 커넥터를 붙여야 한다. 붙기 전에는 해당 작업이 아무것도 게시하지 않고 그 사실만 보고하고 끝난다.

## 공통 시작 절차 (예약 작업 프롬프트에 그대로 들어간다)

1. 저장소 `chagh92-cyber/utopia`를 쓰기 권한으로 세션에 추가하고, 브랜치 `claude/viral-team-planning-fcrkru`를 체크아웃한다.
2. `npm install`을 실행한다.
3. `CLAUDE.md`를 읽고 그 규칙을 따른다.
4. 위 표에서 맡은 절차 파일을 순서대로 실행한다.
5. `npm run check`를 통과시키고, 절차 이름과 날짜로 커밋해 같은 브랜치에 푸시한다.
6. 끝으로 사용자에게 보고한다: 한 일, 사용자가 해야 할 일(승인, 직접 게시), 막힌 것.

## 사용자 승인 방법

2026-11-18부터 `approval`은 `auto`다. 검수를 통과한 소재는 바로 예약되고, 검수가 보류한 소재만
`reports/approval-<날짜>.md` 맨 위에 올라온다. 사용자는 그 소재만 판단하면 된다.

아래는 `batch`로 되돌렸을 때의 방법이다.

`approval`이 `batch`인 동안, 아침 제작이 `reports/approval-<날짜>.md`를 만든다.
사용자는 GitHub에서 그 파일을 열어 승인할 소재의 `[ ]`를 `[x]`로 고쳐 커밋한다(휴대폰 GitHub 앱이나 웹에서 연필 아이콘).
점심·저녁 게시가 `[x]`인 소재만 예약한다.
